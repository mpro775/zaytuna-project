## الملفات الرئيسية

### 🔧 وثائق الباك إند (Backend)
- **API Endpoints**: قائمة شاملة بجميع نقاط النهاية مع أمثلة الاستخدام
- **Database Schema**: هيكل قاعدة البيانات والعلاقات
- **Architecture**: مخططات بنية النظام والتدفقات
- **Modules Documentation**: وثائق مفصلة لكل وحدة في النظام

### 🎨 وثائق الفرونت إند (Frontend)
- **Components**: مكتبة المكونات وطرق استخدامها
- **Pages**: وصف الصفحات وتدفقات المستخدم
- **UI/UX Guide**: إرشادات التصميم والتجربة
- **State Management**: إدارة الحالة في التطبيق

### 🌐 وثائق API
- **OpenAPI/Swagger**: وثائق تفاعلية للAPI
- **Postman Collections**: مجموعات جاهزة للاختبار
- **API Examples**: أمثلة عملية لاستخدام الAPI
- **Error Codes**: قائمة رموز الأخطاء والحلول

### 🧪 وثائق الاختبار
- **Test Coverage**: تقارير تغطية الاختبارات
- **Test Cases**: حالات الاختبار المفصلة
- **Test Results**: نتائج التشغيل والتحليل

## أهمية هذه الوثائق

✅ **دليل للمطورين**: فهم كيفية العمل مع الكود
✅ **تسهيل التكامل**: بين الفرونت إند والباك إند
✅ **دعم الصيانة**: فهم النظام للتحديثات المستقبلية
✅ **ضمان الجودة**: من خلال الاختبارات والوثائق
✅ **تسريع التطوير**: للمطورين الجدد في الفريق

## عملية التحديث

### 🔄 تحديث مستمر
- **API Documentation**: تُحدث مع كل تغيير في نقاط النهاية
- **Database Schema**: تُحدث مع كل تغيير في البنية
- **Architecture**: تُحدث مع التغييرات الكبيرة
- **Test Results**: تُحدث مع كل دورة اختبار

### 📝 معايير التحديث
- أضف تاريخ آخر تحديث في كل ملف
- سجل التغييرات في changelog
- راجع الوثائق عند كل Pull Request
- احتفظ بنسخ سابقة للمراجعة
