# خطة تنفيذ الفرونت إند - لوحة تحكم الزيتون سوفت SaaS

## نظرة عامة على الخطة

يتم تنفيذ الفرونت إند على **26 مرحلة** مقسمة إلى **5 مراحل رئيسية**، مع التركيز على بناء واجهة مستخدم حديثة وقابلة للتوسع. كل مرحلة تحتوي على مهام محددة، معايير القبول، والوقت المقدر.

### المراحل الرئيسية:
1. **الأساسيات والإعداد** (المراحل 1-6)
2. **المكونات الأساسية والتخطيط** (المراحل 7-12)
3. **إدارة الحالة والمصادقة** (المراحل 13-18)
4. **الصفحات والوظائف الأساسية** (المراحل 19-23)
5. **التحسينات والنشر** (المراحل 24-26)

### المهام التفصيلية:

   - إنشاء `UserModule` مع `UserService` و `UserController`
   - إضافة endpoints للمستخدمين: CRUD operations، تغيير كلمات المرور، تبديل الحالة
   - ربط مع `AuthModule` للأدوار والصلاحيات
   - إضافة DTOs للتحقق من صحة البيانات
   - إضافة `UserModule` إلى `AppModule`

2. **إنشاء خدمة المستخدمين في الفرونت إند (UsersService)**
   - إعداد أنواع TypeScript لـ User, Role, Permission
   - إنشاء دوال API للتفاعل مع endpoints الباك إند:
     - `createUser()` - POST /users
     - `getUsers()` - GET /users مع الفلترة
     - `getUserById()` - GET /users/:id
     - `updateUser()` - PATCH /users/:id
     - `deleteUser()` - DELETE /users/:id
     - `changeUserPassword()` - PATCH /users/:id/password
     - `toggleUserStatus()` - PUT /users/:id/toggle-status
     - `getUserStats()` - GET /users/stats/overview

3. **إنشاء خدمة الأدوار (RolesService)**
   - دوال API للأدوار:
     - `createRole()` - POST /roles
     - `getRoles()` - GET /roles

     - `deleteRole()` - DELETE /roles/:id

     - `getRoleStats()` - GET /roles/stats

   - دوال API للصلاحيات:
     - `getAllPermissions()` - GET /permissions
     - `getCategories()` - GET /permissions/categories
     - `getPermissionsByCategory()` - GET /permissions/category/:category

## دليل تكامل PWA مع الباك إند

### نظرة عامة على التكامل
المرحلة 20 تتطلب تكاملاً عميقاً بين الفرونت إند والباك إند لضمان عمل PWA بكفاءة. إليك المتطلبات والتوصيات:

### متطلبات الباك إند للمرحلة 20

#### 1. NotificationModule (جديد)
```typescript
// إضافة NotificationModule في AppModule
@Module({
  imports: [NotificationModule],
  // ... باقي التكوين
})
export class AppModule {}

// NotificationModule endpoints المطلوبة:
POST   /notifications/register-device
POST   /notifications/send/:userId
GET    /notifications/subscriptions/:userId
DELETE /notifications/unsubscribe/:deviceId
POST   /notifications/broadcast (للإشعارات العامة)
```

#### 2. SyncModule (جديد)
```typescript
// إضافة SyncModule للمزامنة
@Module({
  imports: [SyncModule],
  // ... باقي التكوين
})
export class AppModule {}

// SyncModule endpoints المطلوبة:
POST   /sync/data (مزامنة البيانات)
GET    /sync/status/:deviceId
POST   /sync/conflicts/resolve
POST   /sync/queue/process
GET    /sync/changes/:lastSyncTimestamp
```

#### 3. تحديث WebSocket Gateway
```typescript
// إضافة events للمزامنة
@WebSocketGateway()
export class SyncGateway {
  // إرسال تحديثات فورية للعملاء
  @SubscribeMessage('sync_updates')
  handleSyncUpdates(@MessageBody() data: any) {
    // إرسال التحديثات للعملاء المتصلين
  }
}
```

### أفضل الممارسات للمزامنة

#### 1. استراتيجية المزامنة
- **مزامنة ذكية**: مزامنة البيانات الأكثر استخداماً فقط
- **Delta Sync**: إرسال التغييرات فقط وليس البيانات الكاملة
- **Versioning**: استخدام version numbers لتجنب تضارب البيانات
- **Conflict Resolution**: آليات لحل تضارب البيانات

#### 2. إدارة البيانات المحلية
- **IndexedDB**: للبيانات الكبيرة والمعقدة
- **LocalStorage**: للبيانات البسيطة والإعدادات
- **Cache API**: للملفات الثابتة والـ API responses

#### 3. معالجة الأخطاء
- **Retry Logic**: إعادة المحاولة مع exponential backoff
- **Offline Queue**: حفظ العمليات الفاشلة لإعادة المحاولة
- **Error Recovery**: آليات لاستعادة البيانات التالفة

#### 4. الأمان في PWA
- **Service Worker Security**: التحقق من مصداقية الـ SW
- **Data Encryption**: تشفير البيانات الحساسة محلياً
- **Token Management**: إدارة آمنة للـ JWT tokens
- **CORS Policy**: تكوين صحيح للسماح بالـ PWA
